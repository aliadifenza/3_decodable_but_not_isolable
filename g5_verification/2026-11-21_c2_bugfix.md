# C2 feature-selection bug — correction record

**Date:** 2026-11-21
**Affected:** `g5_verification/g5v_probe.py` as run in G5v. Evidence commit `088b6d3`; script sha256 `f85347d777d907ff…`; results sha256 `9ad8bfef…`.
**Fixed in:** `g5v_probe.py` (sha256 `bd585d259f496ddd…`). The repair script `g5r_probe.py` implements the corrected rule from the start.

## The bug

- **Intended (A3 / Decision 1):** C2 ablates the bystander kind's own selected SAE feature set, of size `k` equal to the Substance set.
- **As run:** C2 took `ranked[:k]`, the bystander's top-`k` latents ordered by individual discovery score. That is not the greedily selected set.
- **Example:** at layer 18 with `k` = 1, C2 used latent **14182**, while the bystander's selected latent was **13005**. 13005 ranked second by individual score.

## The fix

- The greedy selection order is now always continued to `K_MAX` = 8 latents and stored as `greedy_order`. The selected set `latents` is a prefix of that order, ending where the gain falls below `GAIN_MIN`.
- `C2 = bystander greedy_order[:k]`.
  - When `k` ≤ the bystander set's size, this **is** the bystander's selected set (truncated).
  - When `k` is larger, the set is extended with the bystander's next greedy picks.

## Verification

- The local test `test_g5v_local.py` still passes.
- A regression check passes: at every layer, the clock's `greedy_order` begins with its selected `latents`, and each C2 set is a prefix of that order.

## Effect on G5v conclusions

**None.** The G5v blockers concerned:
- intervention weakness (|D| ≤ 0.05);
- pronoun positions not being truly non-lexical;
- layer 18 being picked at the edge of the range;
- the coarseness of the active-feature ratio.

None of these depends on which clock latent C2 used. The G5v evidence is preserved unchanged in commit `088b6d3`. Any matching or retention numbers involving C2 in that run were computed with the bugged C2 set and must be read with that in mind.
